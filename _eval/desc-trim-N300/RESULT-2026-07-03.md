# 结果 · desc-trim 触发 benchmark(N300 高同族簇)

> 2026-07-03。6 judge 子代理(3 PRE / 3 POST),各独立看 5 name+description + 10 prompt 选一个。
> ground truth 对 judge 隐藏。

## 打分(三向对比,各 3 run,零方差)

| condition | 准确率 | 说明 |
|---|---|---|
| PRE(原长 desc ~120 词,含 NOT-for) | **100%** (10/10 ×3) | 边界 #2 正确 |
| POST-v1(裸缩 ≤25,去 NOT-for) | **90%** (9/10 ×3) | #2 回归→误 route 到 trace |
| POST-v2(≤25 但保留区分句) | **100%** (10/10 ×3) | #2 恢复 |

三向各 3 次全零方差 = 信号稳、非噪声。**裸缩会回归,智能缩完全恢复。**

## POST-v2 修法(把回归修回去的具体改动)

- log-analysis(24 词,从 156):`Investigate runtime logs for error signatures, trace-ID correlation, and PII/secret exposure in ops incidents; reconstructs execution chains from logs when trace data is absent.` ← 保留"无 trace 时从日志重建链路"这句区分信号。
- trace-call-chain-analysis(18 词):去掉抢戏的"end-to-end chain-completeness verification"。
- 其余 3 个(monitoring/anomaly/rca)用 v1 缩版即可,本就 100%。

## 唯一回归 = prompt #2(边界:无 tracing 从日志重建链路)

- ground truth = log-analysis;PRE 正确、POST 全部误 route 到 trace-call-chain-analysis。
- 机制:裸缩时 log-analysis 丢了"(fallback, 无分布式 trace 时)从 correlation-id 日志重建执行链"这句;
  且 trace 的 POST 里留了"end-to-end chain-completeness verification"。两者一夹,边界 case 被拉向 trace。

## 结论(数据支撑,守 D-048 PRE<POST 纪律)

- **裸缩到 ≤25 词对高同族簇(N300)确会降路由准确率**(100%→90%,可复现)。我预判的风险成立。
- **但不是"≤25 词标准错了"**:19 个 gold 全 ≤25 词且在低同族域(技术设计)路由良好。问题是**高同族簇里裸砍掉 NOT-for 区分信号**。
- **分域策略(定论)**:
  - 低同族域(库大多数):可直接缩到 gold 风格,无回归风险。
  - 高同族簇(N300 ops、以及任何 sibling 高度重叠的簇):缩要**保留关键区分信号**(那句 fallback / NOT-for 边界),哪怕略超 25 或换更紧凑写法;不能裸砍。
- **对 skillctl 的启示**:description 词数门(≤25 warn)是有用信号,但不是硬 error——高同族簇合理超标。保持 warn 级(现状正确)。

- 低同族域:可直接批量缩(先抽一域再跑同款 benchmark 兜底确认无同族回归)。
